# 03: Personal columns are always faked

**What to build:** Columns holding personal data are detected and replaced with fake values, so no Identifying value of these kinds reaches the Synthetic CSV. Detection looks at values as well as column names. A column called `contact` that holds emails is still caught, because SDV alone only checks names. Build this **test-first**: write each failing privacy test before its code. Source of truth: the spec (`docs/SPEC.md`), sections "Type → SDV mapping" and "Privacy rules".

**Blocked by:** 01 (Walking skeleton)

**Status:** ready-for-agent

- [ ] The tool detects these types: `email`, `name`, `address`, `phone`, `card`, `id`. It uses column names and value patterns (e.g. email shape, card numbers, phone numbers).
- [ ] `email`, `name`, `address`, `phone` and `card` columns are generated by Faker (SDV PII sdtypes with `pii: True`). `pii: False` is never set on them.
- [ ] `id` columns get generated values in a matching format. Real IDs are never copied.
- [ ] Privacy tests, one per type, check that no real value of that column appears anywhere in the output. One of them uses a misleading column name (e.g. `contact` holding emails).
- [ ] The Sample CSV script adds emails, names, addresses, phone numbers, card numbers and IDs.
- [ ] The summary lists which columns were faked (names only, no values).
